# Bug: `dueDate`-и бидуни вақт (`"YYYY-MM-DD"`) сервери 500 медиҳад

**Ёфт шуд:** 2026-08-08, ҳангоми сохтани модали таҳрири таск (Фазаи 3, `office-web`).
**Эндпойнтҳо:** `POST /api/tasks` ва `PATCH /api/tasks/{id}` (эҳтимол дигар ҷойҳое, ки `DateTimeOffset?` аз JSON мехонанд, низ таъсир мебинанд)
**Ҷиддият:** Баланд — `500 Internal Server Error` ба ҷои хатои валидатсияи 400, ва санаи оддии "танҳо рӯз" (бе вақт) тамоман кор намекунад.

## Такрористеҳсол

```bash
curl -X PATCH http://localhost:5056/api/tasks/{id} \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"title":"T","priority":"Low","dueDate":"2026-09-01"}'
```

Натиҷа:
```json
{"type":"...","title":"Хатогии сервер","status":500,"detail":"Дар сервер хатогии дохилӣ рӯй дод."}
```

Санҷидашуда, ки танҳо **формати санаи бидуни вақт** (`"2026-09-01"`) сабаб аст — маҳз ҳамин сатр эквиваленти он чизест, ки `System.Text.Json`-и стандартӣ барои `DateTimeOffset?` бидуни `TimeZoneInfo`/offset дуруст парс карда наметавонад ва бо `FormatException`/`InvalidOperationException`-и коркарднашуда меафтад (бинобар ин `500`, на `400`).

Форматҳои дигар дуруст кор мекунанд:
- `"2026-09-01T00:00:00Z"` → `200`, `dueDate` дуруст
- `"2026-09-01T00:00:00+00:00"` → `200`, дуруст
- `null` → `200`, дуруст (тоза кардани сана)

## Чаро муҳим

`title`, `description`, `priority` бидуни хато қабул мешаванд — танҳо `dueDate`-и бидуни вақт мушкил дорад. Ин формат табиист барои ҳама гуна date-picker-и "рӯз, на вақт" (масалан frontend-и мо, `DateInputField`, ки `dayjs(date).format('YYYY-MM-DD')` мебарорад) — бинобар ин эҳтимоли баланд дорад, ки дар истифодаи воқеӣ такрор шавад.

## Тавсия

1. **Ҳатмӣ:** `500` набояд барои input-и нодурусти корбар баргардад — бояд `400 Bad Request` бо `ValidationFilter` бошад (мутобиқи конвенсияи `docs/02-conventions.md`-и ин лоиҳа барои дигар эндпойнтҳо).
2. **Беҳтар:** Санаи бидуни вақт (`"YYYY-MM-DD"`) бояд қабул шавад ва ҳамчун 00:00 UTC (ё бо `DateOnly`→`DateTimeOffset` табдил бо offset возеҳ) пардозиш шавад — на инки рад карда шавад, чунки ин формати табиии ҳама date-picker-ҳои "рӯз" аст.
3. Санҷед, ки оё дигар майдонҳои `DateTimeOffset?` дар лоиҳа (масалан `CreateTaskRequest.DueDate`, эҳтимол дар users/projects низ) ҳамин масъаларо доранд — эҳтимол дар як ҷои марказӣ (custom `JsonConverter` барои `DateTimeOffset?`) ҳал кардан беҳтар аст.

## Роҳи ҳал дар frontend (муваққатӣ, аллакай татбиқшуда)

`office-web`-и `TaskDetailModal.tsx` ҳоло пеш аз фиристодан `"YYYY-MM-DD"`-ро ба `"YYYY-MM-DDT00:00:00.000Z"` табдил медиҳад (бо concatenation-и оддии сатр, **на** тавассути `new Date(...).toISOString()` — он бо timezone-и маҳаллӣ (масалан Осиё/Душанбе, UTC+5) санаро як рӯз ба қафо мебарорад). Ин ҳал кофист барои frontend, вале сабаби аслӣ дар backend боқӣ мемонад ва дигар client-ҳо (мобил, Postman, integration дигар) ба ҳамин хато дучор мешаванд.
