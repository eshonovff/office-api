# Фазаи 14 — Автоматизатсия барои мизоҷон (Instagram, multi-tenancy)

**Ҳадаф:** мизоҷи худсабтшуда (`Customer`) Instagram-и **худашро** пайваст мекунад ва дар
Flow Builder автоматизатсия месозад (коммент → DM, DM → ҷавоб). Триал = **Pro**, 7 рӯз
(қарори корбар, 2026-09-24). Пас аз тамом шудани мӯҳлат автоматизатсияҳо қатъ мешаванд.
**Пешшарт:** Фазаи 13 (обуна) ✅

> **Ин тағйири ҳудуди лоиҳа аст.** `AGENTS.md` мегӯяд "Multi-tenancy — НЕСТ". Корбар онро
> қасдан кушод: кормандон бетағйир мемонанд, мизоҷон каналҳои худро мегиранд. `AGENTS.md`-и
> ҳарду repo дар вазифаи 14.1 нав мешавад.

**Дар ин фаза:** танҳо Instagram + Flow Builder.
**Дар ин фаза НЕСТ** (фазаҳои алоҳида): чатҳои мизоҷ (инбокс), контактҳо, Facebook,
WhatsApp, рассылкаҳо, аналитика, ИИ-менеҷер ва Virale (хизматҳои иловагӣ), саҳифаи модератор.

## 🔒 Қоидаи асосӣ: ҳар саҳифа ва ҳар endpoint аввал нақшро месанҷад

Талаби корбар (2026-09-24): ҳеҷ саҳифа ва ҳеҷ endpoint набояд аввал кор кунад ва баъд хато
диҳад — аввал санҷиши "ин кист ва чӣ ҳуқуқ дорад", баъд иҷозат. Дар ҳар вазифаи ин фаза:

- **Backend:** ҳар endpoint-и нав ошкоро яке аз инҳоро дорад: `RequirePermission(...)`
  (корманд) ё `CustomerOnly` (+ санҷиши тариф/дастрасӣ, агар функсия пулакӣ бошад). Ягон
  endpoint "бе санҷиш" намемонад; endpoint-ҳои қасдан анонимӣ (webhook, OAuth callback)
  рӯйхати маълум доранд ва ҳимояи худро (имзо, state) доранд.
- **Маълумот:** ҷудокунӣ бо филтри худкор (тасмими 2), на бо `Where`-и дастӣ.
- **Frontend:** ҳар route дар `clientLoader`-и layout **пеш аз** render месанҷад: сессия
  (корманд ё мизоҷ), permission (корманд, `ROUTE_PERMISSIONS`), дастрасии тариф (мизоҷ).
  Бе ҳуқуқ — саҳифаи возеҳ ("403" ё "тариф харед"), на хатогии API дар миёнаи саҳифа.
- **Тест:** барои ҳар endpoint-и нав — "актёри нодуруст" (бе токен, корманд ба endpoint-и
  мизоҷ, мизоҷ ба endpoint-и корманд, мизоҷи дигар) → 401/403/404.

## Тасмимҳои тарроҳӣ

1. **Соҳиби канал — як сутун:** `Channel.CustomerId` (nullable; `null` = канали ширкат, яъне
   кормандон). Flow, AutomationRule, Conversation (= контакт), Message, FlowSession,
   ContactTag/Variable аллакай ба `ChannelId` пайванданд — соҳибро аз канал мерос мегиранд.
   Ҷадвали дигар сутуни нав намегирад.
2. **Ҷудокунии худкор, на дастӣ.** Ҷадвалҳои канал дар ~330 ҷои код хонда мешаванд — филтри
   дастӣ дар ҳар ҷо як рӯз фаромӯш мешавад ва маълумот мерезад. Ба ҷояш EF Core **global query
   filter** бо `ITenantContext`-и scoped:
   - **Корманд** (JWT-и default) → танҳо `CustomerId == null`
   - **Мизоҷ** (JWT-и `Customer`) → танҳо `CustomerId == худаш`
   - **System** (Hangfire job-ҳо, аз ҷумла `WebhookProcessor`) → ҳама
   - HTTP-и бе корбар → **ҳеҷ чиз** (ҳимоя, агар endpoint-и анонимӣ ба ин ҷадвалҳо даст занад)

   Филтр дар `Channel` ва тавассути навигатсия дар ҷадвалҳои тобеъ. Тестҳо (EF InMemory)
   исбот мекунанд: корманд канали мизоҷро намебинад, мизоҷ канали мизоҷи дигарро намебинад.
3. **Як аккаунти Instagram — як соҳиб.** `ConnectAsync` ҳоло канали мавҷударо аз рӯи
   `(Type, ExternalId)` дар тамоми система мегирад ва "аз нав пайваст" мекунад — дар
   бисёрмизоҷа ин маънои **гирифтани аккаунти каси дигар**-ро дорад. Агар соҳиби канал дигар
   бошад → 409.
4. **OAuth-и мизоҷ:** `/api/public/channels/oauth/instagram/start|connect` (CustomerOnly).
   `/callback`-и мавҷуда умумӣ мемонад (redirect URI дар Meta тағйир намеёбад) — state
   соҳибро (корманд ё мизоҷ + id) мебардорад, `connect` онро месанҷад.
5. **Маҳдудиятҳо** аз `Subscriptions:Plans[].Limits`: `Accounts` (Pro 1) ҳангоми пайваст,
   `ActiveAutomations` (Pro 10) ҳангоми фурӯзон кардани flow → 409 бо "ба Creator гузаред".
   Триал = маҳдудиятҳои Pro.
6. **Мӯҳлат гузашт:** webhook паёмҳоро боз ҳам сабт мекунад, аммо flow-ҳои мизоҷи бе дастрасӣ
   **иҷро намешаванд**. Канал ва flow-ҳо нест намешаванд — пас аз пардохт фавран аз нав кор мекунанд.
7. **Мизоҷ танҳо Flow Builder мегирад.** Автоматизатсияи соддаи фазаи 10 (`AutomationRule`)
   барои кормандон мемонад. Шаблонҳои `FlowTemplates` умумианд.
8. **Job-ҳои system** (нав кардани токен, backfill-и профил) каналҳои мизоҷро ҳам коркард
   мекунанд — ин лозим аст. Огоҳии нокомӣ (масалан "токен нав нашуд") барои канали мизоҷ ба
   **мизоҷ** (email) меравад, на ба Owner-и ширкат.
9. **Frontend:** Flow Builder-и мавҷуда (~3 100 сатр) такрор навишта намешавад — API-аш
   тавассути React context дода мешавад (кормандон `/api/...`, мизоҷ `/api/public/...`),
   компонентҳо якхела мемонанд.

### 14.3 (2026-09-24)

Ҷойҳое, ки филтри база намепӯшонад — ҳар кадом дида шуд:
- **Камбудии воқеӣ ёфт ва пӯшида шуд:** `ChannelAccessGuard` барои Owner/Admin бе муроҷиат ба
  база "ҳа" мегуфт → `InboxHub.JoinChannel(id-и канали мизоҷ)` Owner-ро ба ҷараёни зиндаи
  паёмҳои мизоҷ ҳамроҳ мекард. Ҳоло guard-и кормандон ошкоро танҳо `CustomerId == null`-ро
  қабул мекунад (дар ҳар 5 метод), новобаста аз филтри база. `ChannelAccessGuardTenantTests`
  (бо DbContext-и **бе** филтр): бе ислоҳ ҳар 5 тест хато, бо ислоҳ сабз. Зинда (SignalR-клиенти
  воқеӣ): Owner → канали ширкат "joined", канали мизоҷ "Дастрасӣ ба ин канал нест".
- Endpoint-ҳои сохтан (`/channels/{id}/flows`, `/flows/from-template`, `/automation-rules`,
  media) аввал каналро тавассути дархости филтрдор мебинанд → 404. `dry-run` канали бегонаро
  ҳоло ҳам 404 медиҳад (пеш 200 бо натиҷаи бе маълумот).
- SQL-и хом: танҳо advisory lock-и таскҳо — ба каналҳо дахл надорад. `Find` истифода намешавад.
- Endpoint-ҳои анонимӣ (webhook, OAuth callback, `/privacy`) ба ҷадвалҳои канал даст намезананд;
  коркарди webhook дар Hangfire (System).
- Огоҳиҳои провайдер ("токен эътибор надорад") барои канали мизоҷ ҳоло ба Owner-и ширкат
  мераванд — маълумот намерезонад, вале қабулкунанда нодуруст → вазифаи 14.6.
